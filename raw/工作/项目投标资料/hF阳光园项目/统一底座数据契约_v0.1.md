# 智慧园区 POC · 统一底座数据契约 v0.1

| 项 | 内容 |
|---|---|
| 适用范围 | 智慧物流 / 智慧消防 / 智慧安防 / 外协物业 / 宿舍管理 五个模块的 POC 演示件 |
| 目标 | 五个模块最终可整合为单文件演示，并支持跨模块联动剧本 |
| 生效时点 | **智慧安防模块动手之前**；物流模块按附录 B 迁移 |
| 状态 | v0.1 草案，待内部评审 |
| 变更控制 | 安防模块落地后修订为 v0.2；此后契约冻结，模块只增数据不改结构 |

> **为什么必须前置**：可复用底座（渲染引擎 48K + CSS 29K + 地图几何 5K）与模块数据是分离的，
> 但只有 ID、事件、人员三套结构统一，跨模块联动才关联得上。这三项一旦各模块自定义，
> 后期整合等于重写。

## 一、空间对象编码规则

### 1.1 五级分层

采用 SOW 1.4.3.2.4.6 要求的园区→建筑→楼层→区域四级，向下扩展设备点位第五级。

| 级别 | 段 | 格式 | 取值来源 | 示例 |
|---|---|---|---|---|
| L1 园区 | PARK | `PK` + 2 位 | 集团 12 园区固定表（见 1.4） | `PK01` |
| L2 建筑 | BLD | 客户既有编号，补零至 3 位 | **沿用客户图纸编号，不重编** | `M06` `M15` `DLI`（电动力） |
| L3 楼层 | FLR | `F`+2 位；地下 `B`+2 位；屋面 `RF` | 建筑楼层表 | `F01` `B01` `RF` |
| L4 区域 | ZONE | `Z` + 3 位 | **优先取 EHS 5S 责任区编码**；无 5S 数据的按实际使用部门管理区域赋码 | `Z003` |
| L5 设备点位 | DEV | `{域}.{类}.{4位序号}` | 各模块设备台账 | `FIRE.SMK.0042` |

### 1.2 完整 ID 与前缀可截断原则

```
PK01-M06-F01-Z003-FIRE.SMK.0042
└L1─┘└L2─┘└L3─┘└L4──┘└──L5────┘
```

**核心约束：任何一级的 ID 必须是完整 ID 的严格前缀。**

这条决定了三件事能不能实现，不是风格问题：

- **逐级穿透**（SOW 要求的园区→建筑→楼层）——下钻即前缀匹配，无需维护父子表
- **聚合统计**——"M06 有多少告警"= 对 `PK01-M06` 做前缀计数，跨模块通用
- **跨模块关联**——剧本 B 里"火警点位 → 该楼栋在册住宿名单"，靠的就是消防事件与宿舍床位共享 `PK01-D02` 前缀

其他规则：

- 全大写、定长、不含中文与空格；中文名称放在 `name` 字段，不进 ID
- 分隔符：级间 `-`，设备内部子段 `.`
- 未知层级用 `--` 占位而非省略（如园区道路无楼层：`PK01-ROAD-----Z012`）；园区级公共对象 L2 用 `PUB`

### 1.3 空间节点结构

```js
SpaceNode = {
  id:      "PK01-M06-F01-Z003",   // 完整 ID
  level:   4,                      // 1~5
  parent:  "PK01-M06-F01",
  name:    "一楼东侧老化测试区",   // 取自 SOW 附录五场景表
  type:    "WORKSHOP",             // 见 1.5 类型字典
  geom:    { shape:"rect", x:412, y:266, w:88, h:54 },  // 见 1.6 坐标系
  attrs:   { area:1240, dept:"电力电子事业部", fireZone:"FZ-06-01" },
  domains: ["FIRE","SEC"]          // 哪些模块在此节点上挂了内容
}
```

### 1.4 园区码表（待客户确认正式简称）

`PK01` 产业园（本期试点）｜`PK02` 智源｜`PK03` 物流园｜`PK04` 储能南区｜`PK05` 总部南区｜

### 1.5 空间类型字典（L2/L4 用）

`WORKSHOP` 车间｜`WAREHOUSE` 仓库｜`HAZMAT` 危化品区｜`LAB` 研发实验室｜`OFFICE` 办公｜
`DORM` 宿舍｜`CANTEEN` 食堂｜`POWER` 配电房｜`PUMP` 消防泵房｜`YARD` 堆场｜`DOCK` 月台｜
`ROAD` 道路｜`PERIM` 周界｜`CONFINED` 受限空间｜`CHARGE` 充电区｜`GATE` 门岗

### 1.6 坐标系（全模块共用，不得各自换算）

| 项 | 值 |
|---|---|
| viewBox | `0 0 1265 845` |
| 原始图纸 | 1265 × 1243 px |
| 纵向压缩系数 SY | **0.68** |
| 比例 | 横向 1 单位 ≈ 1 m；纵向 1 单位 ≈ 1/0.68 ≈ 1.47 m |
| 真实里程还原 | `L = √(Δx² + (Δy/0.68)²)` |
| 不参与压缩 | 文字、图标、车辆与人员图元尺寸 |

> 新模块新增点位一律按此坐标系标注。任何模块**不得**自行改 viewBox 或 SY，
> 否则整合时全部图层错位（物流迭代中已因改比例引发标注碰撞返工，见方法论踩坑清单）。

## 二、事件与告警统一结构

对应 SOW 1.4.3.3.2.2「统一告警接入引擎，对多源告警进行归一化处理」。五个模块产生的一切
告警、隐患、工单、异常，共用同一结构。

```js
Event = {
  evtId:    "EV-FIRE-20260620-0137",
  domain:   "FIRE",              // LOG|FIRE|SEC|OSC|DOM|PLT
  source:   "SENSOR",            // SENSOR|VIDEO_AI|MANUAL|SYSTEM_RULE|THIRD_PARTY
  type:     "FIRE_ALARM",        // 见 2.3 类型字典
  subType:  "SMOKE",
  level:    "L1",                // L1 紧急 / L2 重要 / L3 一般 / L4 提示
  spaceId:  "PK01-M06-F01-Z003",
  deviceId: "FIRE.SMK.0042",
  ts:       "2026-06-20T09:14:22+08:00",
  title:    "M6 一楼东侧烟感报警",
  desc:     "感烟探测器动作，已联动调取覆盖摄像头复核",
  media:    [{type:"snapshot", ref:"IMG_0042_A"}],       // 演示件用占位引用，不内嵌真图
  persons:  ["EMP****2318"],                             // 关联人员，脱敏
  relates:  ["EV-SEC-20260620-0092"],                    // 跨模块关联事件
  status:   "CONFIRMED",
  disposal: [
    {node:"DETECT",  actor:"SYSTEM",      ts:"09:14:22", action:"探测器动作"},
    {node:"VERIFY",  actor:"SEC_PLATFORM",ts:"09:14:35", action:"AI 视频复核确认烟雾"},
    {node:"CONFIRM", actor:"EMP****2318", ts:"09:15:10", action:"值班人工确认火情"},
    {node:"DISPATCH",actor:"SYSTEM",      ts:"09:15:12", action:"一键启动应急预案"},
    {node:"CLOSE",   actor:"EMP****0771", ts:"09:41:03", action:"处置完毕归档"}
  ],
  sla:      {ackLimitSec:60, closeLimitMin:30},
  closeTs:  "2026-06-20T09:41:03+08:00"
}
```

### 2.1 evtId 规则

`EV-{域}-{YYYYMMDD}-{4位序号}`。跨模块剧本中被引用的事件必须使用真实结构的 ID，
不得用 `evt1` 这类临时值——整合时会与其他模块撞号。

### 2.2 状态机（全域统一）

```
NEW → CONFIRMING → CONFIRMED → DISPATCHED → PROCESSING → CLOSED
              ↘ FALSE_ALARM（误报，计入误报率口径）
                             ↘ ESCALATED（超时未响应，自动升级）
```

- `FALSE_ALARM` 是安防模块基线口径（误报率）的唯一来源，必须显式建模
- `ESCALATED` 对应 SOW 物流「超时未接单/未装车/未卸货自动升级」与消防「整改延迟提醒」

### 2.3 事件类型字典（v0.1，各模块可增不可改）

| 域 | type |
|---|---|
| LOG 物流 | `DOCK_OVERTIME` `NO_SHOW` `QUEUE_JUMP` `WEIGH_DIFF` `EXIT_CHECK_FAIL` `DISPATCH_TIMEOUT` |
| FIRE 消防 | `FIRE_ALARM` `DEVICE_FAULT` `DEVICE_OFFLINE` `HAZARD`（隐患） `MAINT_DUE` `PATROL_MISS` |
| SEC 安防 | `PERIM_INTRUDE` `PPE_VIOLATION` `SMOKING` `RESTRICTED_ENTRY` `FALL_DOWN` `VEHICLE_VIOLATION` `5S_VIOLATION` `UNAUTH_DRIVING` |
| OSC 外协 | `CERT_EXPIRE` `TRAINING_OVERDUE` `WORK_PERMIT_MISMATCH` `SERVICE_SLA_MISS` `BLACKLIST_TRIGGER` |
| DOM 宿舍 | `REPAIR_URGENT` `REPAIR_NORMAL` `CHECKOUT_DUE` `FREE_PERIOD_END` |
| PLT 平台 | `INTEGRATION_FAIL` `DATA_SYNC_DELAY` |

### 2.4 告警分级口径

| 级别 | 定义 | 通知方式（对应 SOW 矩阵式分发） |
|---|---|---|
| L1 | 危及人身安全或生产中断 | 弹窗 + 短信 + 语音电话 + 钉钉 |
| L2 | 需限时处置的违规或故障 | 弹窗 + 钉钉 |
| L3 | 一般异常，纳入统计 | 钉钉 |
| L4 | 提示与预警 | 系统内 |

支撑黑名单跨模块联动（SOW 1.4.3.3「严重违规自动触发全集团黑名单禁入，门禁同步失效」、

```js
Person = {
  personId:  "OSC00000731",
  type:      "OSC",              // EMP 员工 | OSC 外协 | VISITOR 访客 | DRIVER 司机 | VENDOR 供应商
  name:      "张*明",             // 脱敏后姓名
  orgId:     "VEN-004",
  orgName:   "外协单位丙",
  orgPath:   ["集团","制造中心","产业园","外协单位丙"],
  roles:     ["WELDER","HOT_WORK"],
  certs:     [{type:"HOT_WORK", no:"****3271", validTo:"2026-11-30"}],
  trainings: [{course:"入厂安全培训", passTs:"2026-05-08", validTo:"2027-05-07"}],
  access:    ["GATE_W","M06_F01","M15_F01"],   // 门禁授权组，用 L2/L3 空间 ID
  blacklist: {flag:false, level:null, reason:null, ts:null, scope:null},
  contact:   {phone:"138****6021"}
}
```

### 3.1 personId 规则

`{类型码}{8 位序号}`，如 `EMP00012345` / `OSC00000731` / `DRV00000042`。
同一自然人在不同模块中**必须共用同一 personId**，否则黑名单联动、考核闭环、
疏散清点全部断链。

### 3.2 黑名单

```js
blacklist = {
  flag:   true,
  level:  "SEVERE",          // SEVERE 严重违规 | LIMITED 限期整改
  reason: "EV-SEC-20260620-0092",   // 必须指向触发事件 ID，不写自由文本
  ts:     "2026-06-20T10:02:00+08:00",
  scope:  "GROUP"            // PARK 本园区 | GROUP 全集团
}
```

`scope: "GROUP"` + 门禁授权 `access` 清空，是剧本 A 的收尾动作。

### 3.3 脱敏规则（全模块强制，沿用物流口径并扩展）

| 对象 | 规则 | 示例 |
|---|---|---|
| 姓名 | 保留姓与末字，中间星号 | 张*明 |
| 工号 | 保留后 4 位 | EMP****2318 |
| 手机 | 中间 4 位星号 | 138\*\*\*\*6021 |
| 身份证 | **一律不出现**，需要时以证件类型 + 后 4 位表示 | 身份证 ****3271 |
| 车牌 | 沿用物流格式 | 皖A·\*\*8 01 |
| 单号 | 沿用物流格式 | YS-2606\*\*-0186 |
| 单位名 | 承运商甲/乙/丙/丁；外协单位甲/乙/丙 | — |
| 园区名 | 总部园区 / 分园区 | — |
| **人脸** | **演示件中一律不使用真实人脸**，用示意框 + 脱敏工号 | — |

> 安防模块涉及人脸授权库，SOW 2.2.3.2 要求开展 PIA。演示件不出现真实人脸是硬红线。

## 四、剧本数据结构

引擎唯一需要改造的地方：现在是一个全局 `idx` 驱动全部视图，升级为 `scenario.steps[idx]`，
剧本可切换、进度独立保存。**在做第二个模块（安防）时顺手完成，不要拖到第五个模块。**

```js
Scenario = {
  scenarioId: "SC-X-02",
  name:       "一次火警的黄金 5 分钟",
  domains:    ["FIRE","SEC","LOG","DOM"],   // 决定需挂载哪些模块图层
  startClock: "09:14",
  durationMin: 26,
  compress:   29,                            // 时间压缩倍数，沿用物流
  steps: [ Step, Step, ... ]
}

Step = {
  t:         0,                      // 相对起始的分钟数
  clock:     "09:14",
  title:     "感烟探测器动作",
  narrative: "M6 一楼东侧老化测试区 …",   // 全屏演示右侧说明栏文案
  view:      "map",                  // map|board|form|phone|func
  focus:     {spaceId:"PK01-M06-F01-Z003", deviceId:"FIRE.SMK.0042"},
  layerOps:  [{layer:"FIRE.detector", op:"setState", target:"FIRE.SMK.0042", state:"alarm"}],
  boardOps:  [{board:"fireOverview", op:"inc", key:"alarmCount"}],
  kpiOps:    [{key:"ackSec", value:13}],
  events:    ["EV-FIRE-20260620-0137"],
  toast:     {level:"L1", text:"一级火警，已推送至现场处置人"},
  mustSay:   true                    // 必讲环节，演示脚本中加粗、不可跳过
}
```

### 4.1 剧本清单（7 条）

| ID | 名称 | 域 | 时长 |
|---|---|---|---|
| SC-LOG-01 | 预约到出园全流程（现有 14 步） | LOG | 完整版 / 精简版双轨 |
| SC-SEC-01 | 一次周界翻越的分钟级闭环 | SEC | ~6 min |
| SC-FIRE-01 | 一次火警的黄金 5 分钟 | FIRE | ~8 min |
| SC-OSC-01 | 外协准入到结算全链 | OSC | ~6 min |
| SC-DOM-01 | 入住—调寝—退宿与费用结算 | DOM | ~4 min |
| **SC-X-01** | **一次外协动火作业**（跨模块） | OSC+SEC+PLT | ~7 min |
| **SC-X-02** | **一次火警**（跨模块） | FIRE+SEC+LOG+DOM | ~9 min |

### 4.2 双轨时长约定

每条模块剧本必须同时提供**完整版**与**精简版**（精简版只保留 `mustSay:true` 的步骤）。
整合演示走精简版 + 两条跨模块剧本，总时长控制在 25 分钟内；分模块深聊时走完整版。

### 5.3 渲染预算（硬约束）

物流只有 33 个月台口；消防按 SOW 附录五是 200 末端压力点 + 69 报警阀 + 400+ 电气监测 +

## 六、命名空间约定

### 6.1 JS

- **允许的全局变量只有一个：`window.CP`**。模块内不得声明裸全局函数或常量。
- 模块内容挂在 `CP.{域}` 下，如 `CP.FIRE.buildOneMap()`、`CP.SEC.data.cameras`。
- 引擎公共能力挂 `CP.core.*`：`CP.core.map` / `CP.core.timeline` / `CP.core.event` /
  `CP.core.board` / `CP.core.person` / `CP.core.check`。

### 6.2 DOM id 与 CSS

| 类型 | 格式 | 示例 |
|---|---|---|
| DOM id | `cp-{域小写}-{语义}` | `cp-fire-layer-hydrant` |
| CSS class | `cp-{域小写}__{块}--{修饰}` | `cp-sec__alarm-card--l1` |
| 自定义事件 | `cp:{域小写}:{动作}` | `cp:fire:alarm-confirmed` |
| **SVG defs id** | **必须带域前缀** | `cp-fire-grad-alarm` |

> SVG 特有坑：`<marker>` / `<linearGradient>` / `<filter>` 的 id 是文档级全局，
> 五个模块各自定义 `arrow`、`glow` 必然覆盖，且不报错、只是渲染错乱，极难排查。

### 6.3 文件内区块标记

单文件整合后靠注释分段，便于定位与降级剥离：

```
/* ==== CP.CORE BEGIN ==== */ … /* ==== CP.CORE END ==== */
/* ==== CP.FIRE BEGIN ==== */ … /* ==== CP.FIRE END ==== */
```

每个模块区块用独立 `try/catch` 包裹并向 `CP.core` 上报失败，
单模块渲染异常只显示该模块占位提示，不影响其他视图（避免整合后成为单点故障）。
