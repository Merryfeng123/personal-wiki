## 三、业务方案要点

### 3.1 园区物理建模（依客户图纸 1:1 还原）

- **道路**：菖蒲路为东西向主物流通道（双向）；阳光大道 + 规划支路为南北主通道；其余南北支路单向；北区绕车间顺时针环线。
- **门岗七个，其中三个通行货车**：西门（主物流进出口，长宁大道侧）、东门（次物流进出口，量子大道侧）、南3门（辅助物流出口，铭传路侧）；北1门、北2门、南1门、南2门为通勤访客，货车不通行。门岗位置严格与道路对齐。
- **月台 33 个口**：红色 27 个为内外部车辆共用月台口，蓝色 6 个为内部转运车专用口。其中 23 个红口划分为 A–E 五个功能月台组（M7 五车间西侧 6 位、M6 四车间西侧 4 位、M4 十车间东侧 4 位、M10 7A车间东侧 5 位、M15 车间西侧 4 位）。
- **地磅 3 台**：西门内、东门内、南3门内，遵循"就近过磅不穿园"原则。
- **月台停留时限**：外部车辆 2H，内部与外协车辆 1H（超限触发预警与改派）。

### 3.4 时间轴（14 步，模拟 08:40–10:50 共 130 分钟）

预约 → 签到 → 排队叫号 → **危废/内转优先卸货** → 入园放行 → 进场称重 → 园内导航至月台 → **四车并行作业（月台超时预警）** → **转月台二次排队** → 第二月台完成 → 西南角南3门出货 → 离场称重与净重校验 → 出门证审查 → 出园闭环

- 第 8 步：C-01 月台超时占用 2h12m → 一级预警 → 待入车辆自动改派 C-04（地图脉冲高亮 + 箭头标注框 + 月台看板同步）

### 3.5 KPI 口径（11 个时间戳）

| 指标 | 口径 |
|---|---|

| 平均装卸时长 | 开工 → 完工 |
| 平均转场时长 | 离台 → 下一月台上台 |

## 四、技术实现要点（可直接复用）

### 4.1 总体做法

- **单文件 HTML**，无任何外部依赖，图片以 base64 内嵌，双击即可演示，便于分发。
- **数据与渲染分离**：道路、建筑、月台、门岗、地磅、车辆路线、时间轴、看板数据全部是数组/对象，渲染函数只读数据。改业务只改数据，不动渲染。
- **多视图共用一条时间轴**：一个 `idx` 驱动全部视图，切视图不打断播放进度。
- **地图实例迁移而非复制**：全屏演示与流程模拟共用同一个 DOM 地图实例，切换时整体搬移，状态连续。

### 4.2 地图建模

- viewBox 直接采用客户图纸像素尺寸（1265×1243），坐标零换算，**1 地图单位 ≈ 1 m**。
- 因图纸接近正方形（1.02:1）不利于宽屏演示，**纵向按 SY=0.68 压缩**至 1265×845（1.50:1），与全屏演示框比例吻合（各分辨率下占框宽 92–100%）。压缩只作用于几何，**文字与车辆尺寸不压缩**；计算真实里程时按 SY 还原。
- 月台垛口既是静态图元（红/蓝语义）又是状态图元（演示时变色），两套语义叠加。

### 4.3 车辆运动模型

- **俯视车型 + 纯角度旋转**。侧视车型必须用镜像变换表达反向，而浏览器在镜像与旋转之间插值会经过退化状态，视觉上像原地翻身。
- 转向按**最短弧**计算：`((raw - angle + 540) % 360) - 180`，角度连续累加，绝不绕远路。
- **整条路径用 requestAnimationFrame 连续插值**，梯形速度曲线（起步加速 18% / 匀速 62% / 到位减速 20%），中间所有转折点匀速通过。逐段 CSS 过渡会让每个拐角都停顿。
- 速度按园区限速 20 km/h × 时间压缩 29 倍换算，播放档位越慢车速同比放慢。32 次移动里程 32–645 m，时长 0.8–4.0 s。

### 4.4 轨迹线

- 每车一条固定**分道偏移**（±10.5 / ±3.5），偏移方向按**道路轴向**固定（竖向路左右错开、横向路上下错开），**不能按行驶方向的法线**——否则两车对向行驶会算到同一侧仍然重合。
- 叠加 ±2.2 的方向微偏移，使同一辆车的往返也能区分。
- 拐角先求相邻偏移线的交点作为顶点，再用二次贝塞尔倒圆角，路径连续平滑。

### 4.5 每轮改动都做程序化自检

这是保证质量的关键手段。已建立的检查项：

- HTML 结构闭合校验、JS 语法校验、元素 id 引用完整性
- 建筑两两重叠检测、月台垛口是否贴宿主建筑边、门岗是否与道路对齐
- 车辆停靠点是否等于月台垛口中心、看板占用窗口是否与实际停靠步骤一致
- 轨迹是否穿越建筑、**行驶方向是否逆规划单向**、转向角分布（应全部 ≤90°）
- 全步骤两两车辆间距检测（防重叠）
- 标注文字碰撞检测、脱敏词残留检测、厂商名残留检测

## 五、迭代踩坑清单（对新模块最有参考价值）

| 问题 | 表现 | 根因与对策 |
|---|---|---|
| 图纸分批到位 | 前后返工十余轮 | 地图、月台、行车线、门岗是分三次拿到的。**新模块务必先集齐图纸与规范再动手** |
| 1:1 建模不利演示 | 宽屏下大量留白 | 按演示框比例做定向压缩，只压几何不压内容 |
| 近正方形地图 | 侧栏挤压、地图只有 300px | 需重排布局：地图独占一栏满高，其余卡片移到另一栏 |
| 侧视车型 | 转向时像翻身 | 改俯视车型 + 纯角度旋转 |
| 逐段 CSS 过渡 | 每个拐角停顿 | 改 rAF 整条路径连续插值 |
| 轨迹重叠 | 两车同路只见一条线 | 按道路轴向分道偏移 |
| 消除掉头引入逆行 | 为了不掉头改了路线，结果逆着规划单向走 | **任何路线调整都要回头核对规划单向方向** |
| 判断顺序写错 | 已出园车辆轨迹整条消失 | `k<0` 必须先于 `k<enterIdx` 判断 |
| 压缩后标注碰撞 | 路名被门岗压住、地磅名压住门岗名 | 每次改比例都要重跑标注碰撞检测 |
| 多车同点 | 西门入园两车重叠 | 全步骤两两间距检测 + 停靠点错位 |

## 七、方法论提炼（迁移到其他模块）

物流 POC 能被认可，是因为同时具备四个条件。**评估任何新模块是否适合同种形态，先看这四条**：

1. **空间维度**——有东西在地图上动
2. **强时序**——步骤之间有明确因果，能串成几分钟的闭环
3. **可量化痛点基线**——有"改善前 vs 改善后"的数
4. **现成的规划依据**——客户自己的图纸与规范，不是我们编的

### 做法上的五条经验

1. **先定"验什么"再定"演什么"**：POC 三目标（流程能跑通 / 数据能算清 / 策略能复制）先于任何界面设计。
2. **场景矩阵先行**：把必须覆盖的场景列成 S1–S6 这样的矩阵，避免上线后才发现"这类情况管不了"。
3. **量化口径必须先签字**：口径不定，试点数据无法与现有台账对比，效益无法认定。
4. **用客户自己的图纸建模**：可信度的来源不是画得好看，而是"这就是我们园区"。
5. **一个壳、多模块切换**：不要做成多个独立 HTML，"一次建模、多域复用"本身就是最强卖点。

## 八、对其余四个模块的初步判断（待 SOW 确认后调整）

| 模块 | 建议 | 理由 | 可复用资产 |
|---|---|---|---|
| **智慧外协管理** | 第一批做，流程动画 | 流程链比物流还长（入场申请→资质审核→安全培训→门禁授权→作业票→巡检→结算→退场），与物流的承运商/黑白名单/违规闭环高度同源 | 地图、门禁、黑白名单、考核闭环 |
| **智慧安防监控** | 第一批做，需锁定场景 | 与物流共用感知底座（LPR/围栏/视频 AI），可讲"一次建模、多域复用"。风险是易做成视频墙截图集，必须锁定周界翻越、尾随、未穿戴、人车混行等具体场景；真实人脸一律不用 | 地图、LPR、电子围栏、视频 AI |
| **智慧消防** | 第二批，换叙事 | 事件驱动而非稳态流，形态应为"一次火警的黄金 5 分钟推演"。两个注意：无历史基线需另想口径；锂电（电芯/PACK 车间）特殊消防客户极敏感，须标明"演示管理与联动逻辑，不替代消防主机法定联动" | 地图、道路模型、疏散点 |
| **智慧宿舍管理** | 换形态，不建议做流程动画 | 空间上宿舍楼在地图上只是几个小方块无流动可看；时间上入住/退宿/查寝/水电都是慢变量。价值在台账与数据，适合做"床位一张图 + 表单原型 + 看板" | 基本无 |

### 下一步建议动作

1. **提供一期 SOW 与功能要求梳理**——这是决定四个模块 POC 形态的关键，需要看清三件事：
   - 验收条款的颗粒度（一句话条款 → POC 的重点是拆解本身；已列功能点 → 做能力映射表）
   - 集成边界（甲方提供接口还是乙方负责对接，直接决定能不能放心演联动）
   - 与 IOC 的关系（看板归谁做、数据谁上送、页面嵌不嵌）
2. **先出一份四模块可行性与形态判断表**（2–3 页），对齐"做什么、做到什么程度"，再动手做 HTML。
3. **先做一个模块跑通"同壳多模块"的模式**，验证客户认这个路子，再往下铺。四个同时开工质量会稀释。
